# Claim model

The caller selects `subject`, `claim`, `policy`, semantic requirement and requested guarantee/domain obligations. The receipt declares what it covers. Agreement is evaluated, never assumed. The Git subject names an exact regular-file digest, commit, root tree, relative path, identity and version. Git object SHA-1 is used for compatibility, with artifact SHA-256 as a separate identity; neither establishes GitHub acceptance or author identity.

The implemented base claim is SHA256_EQUALS. RVR receives an independently selected expected digest after verifying that both supplied native claims agree with the signed product statement. Native evaluated bytes must agree with the attachment/Git subject. Saved native canonical results must agree with their committed attachment. Native positive and negative outcomes remain separate from REPRODUCED/DIVERGED/CANNOT_RECOMPUTE.

Semantic ABI describes claim, authority, subject, scope, time, assumptions and evidence requirements. Producer labels cannot supply observed authority or execution. The current base profile establishes local recomputation authority over supplied bytes only. Its semantic link does not establish real-world truth or production execution. Historical receipts retain their original boundaries; no migration invents missing signature, authority, freshness or execution.

PRF guarantee contexts are separate caller-owned bounded premises: accepted basis ID, supported guarantee IDs and obligation observations. The producer cannot provide these through its signed payload. The product checks exact dependency/obligation preservation, but does not prove global basis completeness, caller acceptance authority or arbitrary predicate soundness. UNKNOWN dependencies withhold a guarantee before separate FALSE obligations.

Interpoll caller requirements select the exact authorized signed envelope and actor/namespace/target tuple. Observed accepted action and retries come only from committed evidence. A different valid signature cannot substitute another actor or action. Historical key-control checks do not imply fresh admission, SQL commit atomicity, target visibility or a real human view.

Chronicle's native derived-entry identity is preserved. Sequence, predecessor and current-state rules are explicit product extensions. Later divergence does not invalidate an exact historical observation, but cannot satisfy a current-state query. Optional full-envelope binding hashes the complete supplied history envelope; native derived-entry equality alone does not bind the original envelope bytes.

The `evidence` request array is reserved and empty in v1; attachments live in the signed bundle manifest. Unknown required layers and unknown object fields are rejected, not silently ignored.
