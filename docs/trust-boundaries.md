# Trust boundaries

| Established | Does not establish |
|---|---|
| Attachment/hash/root equality | Source truth, authority or execution |
| Product Ed25519 signature | Correctness, official Git author or provider authentication |
| Interpoll Schnorr key control | Human identity, truthful viewing or SQL deployment behavior |
| Native RVR REPRODUCED | A positive predicate or another execution |
| Local stochastic replay | Authentic RNG origin, entropy or unbiased selection |
| Native QEV consistency | Provider authentication or physical QPU execution |
| Capsule/Merkle/visual carrier validity | Semantic authority |
| Preserved bounded guarantee relation | Complete/sound global dependency basis |
| Declared package/runner | Actual semantic PASS |
| Cost/benchmark metric | Security proof |

All demo signatures, actions, artifacts, counts and controls are fresh synthetic fixtures. Public synthetic test seeds are not deployed credentials. No provider token, private Vértice implementation or captured third-party provider payload is included. Metadata explicitly required by native frozen profiles is retained with original rights and meaning; a historical origin label is never authenticated by the product.

Trust keys and bounded guarantee premises are caller policy inputs. The installed product/checker and local operator environment are trust boundaries; source locks detect accidental/release drift, not a compromised host rewriting both program and lock. The new product's self-tests are not an independent third-party certification.

PQ interfaces cannot promote MOCK or STRUCTURAL providers into real cryptographic verification. Empty packs remain no evidence. ML-DSA/Solidity research remains experimental/historical according to exact upstream state. No full PQ conformance or production security level is asserted.

The stochastic example consumes one committed byte using modulo selection. It deliberately claims deterministic replay only; modulo bias and lack of entropy/provider evidence prevent a randomness-quality guarantee. Candidate set, stream digest, cursor and domain are explicit inputs.

Ledger anchors reserve Ethereum, XRPL and off-chain boundaries. No transaction inclusion, network consensus or finality is inferred from a supplied transaction identifier. Live adapters remain unsupported.

The web UI is a local inspector. It accepts raw JSON, clears stale verdicts when inputs change and displays layer-native data. It binds localhost only, checks Host/Origin, bounds bodies/concurrency, serves fixed paths and uses CSP. These controls are not a production web-service clearance.
