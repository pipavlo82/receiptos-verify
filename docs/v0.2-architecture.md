# v0.2 architecture

This is an additive versioned boundary over the public v0.1.0 implementation. The public tag peels to `62cd3e59c8f568496ed087d55f0aec3d63363b0a`, tree `8a5de5a3735e04f3f45cf164b59da17289693bc2`. The historical pre-publication candidate is not the public base. Original request/bundle/report v1 schemas, thirty vectors and fourteen mutation definitions remain regression inputs.

`verify()` dispatches request v2 to `verifyV2()`; otherwise the audited v1 admission and verification path remains in place. V2 has separate schemas, admission, signing domain and projection. V1 capsules continue to use their explicit v1 interchange contract; no compatibility is inferred for v2 capsules.

The pipeline is strict admission, canonicalization, committed-attachment/payload integrity, native Crystal root verification, product Ed25519 authentication, requested/evidence surface comparison, pinned native recomputation, evidence sufficiency, optional PRF transfer and Chronicle continuity, then a finite product projection. Computations may be performed before all gates are established so a report can preserve each observation. This does not authorize a gate bypass.

All fourteen layers remain visible. Native outcomes and replay are independent fields. The Semantic ABI compatibility layer executes the public neutral manifest validator and linker; optional detached pair evaluation never invents an expected pair from evidence. Crystal/RVR keep their public pins. The Trustless integration executes the main `scan_subject_binding.v0` checker and canonical conformance runner, preserving the actual artifact and its self-grading runner interpretation separately. Interpoll executes the unchanged public Schnorr verifier and a bounded product retry relation. PRF executes the unchanged main award/actual-settlement relation and a separately labeled experimental transfer rule derived from open PR14.

The generic core contains no Ethereum or XRPL semantics. The existing ledger boundary reserves off-chain/unanchored, Ethereum and XRPL. There is no live chain implementation or finality claim.

Evidence cannot select executable paths, commands, network destinations or source pins. No upstream worktree is changed. Only selected neutral public source files are vendored, with byte hashes, original grants and contributor evidence. See the provenance and third-party notices.

## Bounded claims

V2 does not implement arbitrary logical entailment. It supports exact structured claim-surface identity plus independently supplied premise checks. Primitive claim kinds have explicit native bindings:

| Kind | Actual relation | Permitted evidence-declared scope |
|---|---|---|
| SHA256_EQUALS | Native RVR digest predicate and saved-artifact replay | `{"evidence_member":"artifact"}` |
| TRUSTLESS_CHECK | Pinned scan-subject-binding case over the exact committed input | Exact case ID and `scan-subject-binding` relation |
| SIGNED_ACTION_TRACE | Signed intent, supplied accepted/attempt/observation trace and trace commitment | Native namespace and `supplied-trace-only` observation |

Other signed declarations cannot expand these capabilities. In particular a clean toy scan is not poisoning absence, supplied action observations are not authenticated server execution, and receipt publisher authority is not provider/hardware authority.

PRF is a separately selected award/settlement obligation. Its caller-owned input digest and expected native result bind that tuple. It does not transfer the current RVR/Trustless result automatically. A reproduced negative PRF tuple can retain a PRESERVED transfer relation while its native result remains negative.

## Deterministic identity

Canonical inputs and semantic/native result identities are deterministic. Execution command receipts include the actual host paths, runtime versions and captured stdout/stderr; those operational fields are outside semantic identity. The v0.2 determinism gate compares complete semantic reports after removing only execution `argv` fields, and retains exact raw command receipts separately. No native verdict, reason, source pin, evidence digest or claim field is excluded.
